## Project Summary

This project controls a two-wheel car with two STEP/DIR stepper drivers and
an MPU6050. It does not use HMC5883L or any other magnetometer.

The step pulses are generated by the existing hardware PWM timers. The main
loop samples the MPU6050 every 5 ms and the car controller can use the gyro
and integrated yaw to make short-term straight-line corrections.

## Pin Assignments

The existing `empty.syscfg` is kept unchanged.

| Function | SysConfig signal | Pin |
| --- | --- | --- |
| Right wheel STEP | `cloud_1_TILT` / TIMA0 CCP2 | PB0 |
| Left wheel STEP | `cloud_2_PAN` / TIMG6 CCP0 | PB2 |
| Right wheel DIR | manually initialized GPIO output | PB13 |
| Left wheel DIR | manually initialized GPIO output | PB3 |
| MPU6050 SDA | `I2C_1` | PA16 |
| MPU6050 SCL | `I2C_1` | PA17 |
| MPU6050 INT | `GPIO_MPU_INT/PIN_INT` | PB24 |

## Motion API

`src/car_control.h` exposes the differential-drive interface:

```c
Car_SetVelocity(300, 0);    /* forward */
Car_SetVelocity(-300, 0);   /* reverse */
Car_SetVelocity(0, 250);    /* rotate / turn */
Car_Stop();
```

Positive `linear_rpm` is forward. `turn_rpm` is a wheel-speed differential.
The example `main` deliberately starts stopped. Add a command after successful
IMU initialization when a standalone motion test is wanted.

The default left/right direction polarity assumes the motors are mirrored:
`CAR_LEFT_FORWARD_DIR` is `STEPPER_DIR_CCW` and
`CAR_RIGHT_FORWARD_DIR` is `STEPPER_DIR_CW`. Swap those definitions in
`src/car_control.h` if the assembled vehicle moves backward.

The yaw hold is only a short-term correction because MPU6050 yaw has no
absolute reference and will drift over time. The controller stops both wheels
on MPU communication failure or when roll/pitch exceeds 35 degrees.

### Device Migration Recommendations
This project was developed for a superset device included in the LP_MSPM0G3507 LaunchPad. Please
visit the [CCS User's Guide](https://software-dl.ti.com/msp430/esd/MSPM0-SDK/latest/docs/english/tools/ccs_ide_guide/doc_guide/doc_guide-srcs/ccs_ide_guide.html#sysconfig-project-migration)
for information about migrating to other MSPM0 devices.

### Low-Power Recommendations
TI recommends to terminate unused pins by setting the corresponding functions to
GPIO and configure the pins to output low or input with internal
pullup/pulldown resistor.

SysConfig allows developers to easily configure unused pins by selecting **Board**→**Configure Unused Pins**.

For more information about jumper configuration to achieve low-power using the
MSPM0 LaunchPad, please visit the [LP-MSPM0G3507 User's Guide](https://www.ti.com/lit/slau873).
